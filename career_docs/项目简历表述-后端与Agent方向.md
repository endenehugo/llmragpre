# 项目简历表述：Python 后端 / Agent 方向

本文档用于将当前项目整理为可直接写入简历的项目经历描述，面向两个目标岗位方向：

- Python 后端实习生
- Agent / AI 应用开发实习生

编写原则：

1. 使用 STAR 原则组织描述
2. 优先使用代码中可验证的量化信息
3. 突出个人贡献和技术深度
4. 使用强动词表达行动与结果
5. 单条表述控制在 3-5 行，避免空泛

## 一、Python 后端实习生方向

### 版本 A：完整版（至少 5 点）

1. 围绕求职助手多场景问答需求，主导基于 Flask 的后端分层开发，按 Handler、Service、Repository 拆分核心链路，落地会话、文档、图片等 20+ 接口，降低业务耦合并提升后续功能扩展效率。

2. 面向历史会话可追溯场景，设计 MySQL 持久化方案，统一存储会话、消息与文档元数据，并通过自动建表机制打通创建、续聊、回放链路，支撑多轮对话与文档绑定能力落库。

3. 针对简历上传与解析场景，搭建文档处理流水线，支持 TXT、PDF、DOCX 3 类文件的保存、解析、异常回滚与纯文本落盘，为后续检索、评分和问答模块提供稳定输入。

4. 为解决不同用户资料串扰问题，设计会话级 FAISS 索引隔离方案，按 conversation_id 动态构建、重建和删除向量索引，保证简历与岗位材料在检索链路中的数据边界清晰可控。

5. 针对短问题和文件概述类问题召回偏弱的情况，优化检索服务，加入“阈值检索 + 相似度兜底”双阶段策略，并把原始文件名写入索引文本，提升按文件名提问时的检索命中能力。

6. 面向接口安全与文件访问风险，补充 conversation_id、文件名、图片 URL、扩展名和 MIME 白名单校验，覆盖上传、访问与图片渲染入口，增强后端接口的鲁棒性与安全边界。

7. 为提升部署可维护性，完善 dev/test/pre/prod 4 套环境配置切换机制，并补充 WSGI 与 Gunicorn 启动配置，处理 LLM 请求超时和单 worker 会话一致性等部署问题。

### 版本 B：简历精简版（建议投递时选 3-5 条）

1. 主导基于 Flask 的求职助手后端分层开发，完成会话、文档、图片等核心接口设计与实现。

2. 设计 MySQL 持久化链路，支持会话、消息、文档元数据落库及历史会话续聊。

3. 搭建 TXT、PDF、DOCX 3 类文档解析与落盘流程，为问答、评分和导出模块提供统一数据输入。

4. 实现会话级 FAISS 索引隔离与双阶段检索优化，提升简历问答场景下的召回稳定性。

5. 完善参数校验、文件访问安全和多环境部署配置，增强系统鲁棒性与可维护性。

## 二、Agent / AI 应用实习生方向

### 版本 A：完整版（至少 5 点）

1. 围绕求职辅导场景，设计并实现基于 LangChain 的求职助手 Agent，整合会话问答、文档 RAG、工具调用和多模态分析 4 条能力链路，支持从简历问答到岗位分析的连续式交互。

2. 面向用户上传简历后的定制化问答需求，搭建会话级 RAG 流程，串联文档解析、文本切分、Embedding、FAISS 建库与检索增强生成，实现围绕单个会话资料的上下文化回答。

3. 针对求职场景中关键词强、问法短、语义分散的问题，优化为“向量检索 + BM25 检索 + 重排序”的混合检索方案，并保留阈值失败兜底逻辑，提升复杂查询下的召回稳定性。

4. 为降低长对话上下文膨胀带来的模型开销，设计历史消息压缩机制，在超过阈值后自动摘要早期对话、保留最近消息，并补充关键信息提取逻辑，增强多轮对话连续性。

5. 针对大模型回答可解释性不足的问题，实现上下文校验与引用标注模块，对回答中的关键断言做支撑性分析，并为命中的内容追加来源说明，降低 RAG 场景下的幻觉风险。

6. 面向真实求职流程，封装 JD 解析、简历评分、项目润色、模拟面试等 7 类 Agent 工具，并通过 tool calling 机制按用户意图动态调用，形成岗位分析到简历优化的闭环能力。

7. 围绕招聘截图输入场景，接入 Qwen-VL 多模态模型，实现图片内容识别、JD 文本抽取与简历联动评分，打通“截图上传 -> JD 提取 -> 匹配分析”的自动化链路。

8. 针对 LLM 返回 JSON 不稳定的问题，设计结构化结果容错方案，加入代码块提取、括号匹配、坏 JSON 修复与字段标准化处理，提升 JD 分析、评分和项目改写模块的可用性。

### 版本 B：简历精简版（建议投递时选 3-5 条）

1. 设计并实现求职助手 Agent，整合会话级 RAG、工具调用与多模态能力，支持求职场景连续交互。

2. 搭建文档解析、向量化、索引构建与检索增强生成链路，实现围绕用户简历的定制化问答。

3. 优化混合检索策略，结合向量召回、关键词检索与重排序，提升短问题和专业术语场景下的召回效果。

4. 实现上下文压缩、回答校验与引用标注机制，增强多轮对话场景下的可解释性与稳定性。

5. 封装 JD 解析、简历评分、项目润色、模拟面试等 7 类工具，形成完整的求职辅助 Agent 链路。

## 三、使用建议

1. 如果投 Python 后端实习生，优先使用“后端方向版本 B”，再从版本 A 中补 1-2 条最能体现工程深度的内容。

2. 如果投 Agent / AI 应用实习生，优先使用“Agent 方向版本 B”，再从版本 A 中补 1-2 条最能体现 RAG、工具调用、多模态或结构化输出治理的内容。

3. 不要在简历中写没有证据支撑的量化结果，例如准确率提升、QPS 提升、幻觉率下降等；当前更适合写“支持了什么能力”“解决了什么问题”“采用了什么方案”。

4. 最终投递时建议每个项目保留 4-5 条即可，避免单个项目过长，影响整体简历阅读效率。

## 四、谨慎表述项

- 可以写：支持 3 类文档格式、4 套环境配置、7 类 Agent 工具、会话级索引隔离、双阶段检索、多模态截图分析。
- 不建议直接写：高并发、生产级大规模落地、准确率提升百分之多少、支撑多少用户、响应时间降低多少。
