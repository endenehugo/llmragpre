## 根本原因

**`langchain-core` 版本从 `0.3.86` 被意外升级到了 `1.4.0`，导致与 `langchain==0.3.25` 不兼容。**

### 版本对比

| 包名 | `requirements-prod.txt` 锁定版本 | 实际安装版本 | 状态 |
|------|----------------------------------|-------------|------|
| `langchain` | `0.3.25` | `0.3.25` | ✅ 一致 |
| `langchain-core` | `0.3.86` | **`1.4.0`** | ❌ 不一致 |
| `langchain-community` | `0.3.25` | `0.3.25` | ✅ 一致 |

### 详细分析

1. **在 `langchain-core` 1.x 中，`langchain_core.memory` 模块已被移除**。`BaseMemory` 类被迁移或废弃，不再存在于 `langchain_core.memory` 路径下。

2. **`langchain==0.3.25` 仍然使用旧版导入路径**。其内部文件 `langchain/memory/chat_memory.py` 第10行执行：
   ```python
   from langchain_core.memory import BaseMemory
   ```
   该路径在 `langchain-core>=1.0` 中已不存在。

3. **升级诱因**：conda 环境中额外安装了以下依赖 `langchain-core>=1.0` 的包：
   - `langgraph==1.2.8`
   - `langgraph-checkpoint==4.1.1`
   - `langgraph-prebuilt==1.1.0`
   - `langchain-openai==1.1.7`
   
   这些包在安装时强制将 `langchain-core` 升级到了 1.x，覆盖了 `requirements-prod.txt` 中的版本锁定。

## 解决方案

### 方案一：快速修复（推荐）

将 `langchain-core` 降级回 `0.3.86`，使其与 `langchain==0.3.25` 兼容：

```bash
pip install langchain-core==0.3.86
```

**注意**：降级后，`langgraph` 等依赖 `langchain-core>=1.0` 的包可能无法正常工作。如果项目中未实际使用 `langgraph`，可一并卸载：

```bash
pip uninstall langgraph langgraph-checkpoint langgraph-prebuilt langgraph-sdk langchain-openai -y
pip install langchain-core==0.3.86
```

### 方案二：全面升级（长期方案）

将所有 langchain 相关包升级到相互兼容的 1.x 版本，并修改项目代码以适配新 API。

**1. 升级包版本：**

更新 `requirements-prod.txt`：

```
langchain>=1.0.0
langchain-core>=1.0.0
langchain-community>=0.4.0
```

然后执行：

```bash
pip install --upgrade langchain langchain-core langchain-community
```

**2. 修改代码：**

`langchain-core` 1.x 中 `BaseMemory` 的导入路径已变更。需要修改 `chat_memory_handler.py` 中的相关导入。

`langchain` 1.x 中 `ConversationBufferMemory` 可能已被废弃或移到 `langchain_community` 中，需要根据实际情况调整。

> ⚠️ 方案二改动较大，可能涉及多个 handler 文件的修改，建议在充分测试后再上线。

## 预防措施

1. **使用虚拟环境隔离**：确保项目使用独立的 conda 环境或 venv，避免全局包污染。

2. **锁定全部依赖**：使用 `pip freeze > requirements-lock.txt` 生成完整的依赖锁定文件，而非仅锁定顶层包。

3. **安装时严格遵循锁定文件**：
   ```bash
   pip install -r requirements-prod.txt --no-deps  # 仅安装指定包
   # 或
   pip install -r requirements-lock.txt  # 使用完整锁定文件
   ```

4. **检查依赖冲突**：安装新包前使用 `pip check` 检查版本兼容性。

## 影响范围

该错误发生在应用启动的导入阶段，会导致整个应用无法启动。所有使用 `langchain.memory` 模块的功能均受影响，包括：
- `ChatMemoryHandler`（`app/handler/chat_memory_handler.py`）
- 任何其他间接导入 `langchain.memory` 的模块
